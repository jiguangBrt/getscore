# 视频、任务定义与奖励复查

2026-11-04。仅分析已有记录，不修改 v2 环境/权重，不启动训练。以下阈值均为下一版讨论建议。

## 直接观察与核对

用户所指 `eval-12.0h-actor1-place.mp4` 实际案例为 place-01，目标是黄白杯，原场景来自书放入收纳盒的 STUDY_SCENE1。提示为 `place the yellow and white mug upright nearby on the table`。

- [base 关键帧](/home/jh/getscore/outputs/rl-skills-long-20261103/diagnosis-20261104/eval-baseline-actor1-place.png)：开始已手持杯子，随后将杯子搬向收纳盒。
- [RL 后关键帧](/home/jh/getscore/outputs/rl-skills-long-20261103/diagnosis-20261104/eval-12.0h-actor1-place.png)：同样搬向收纳盒，后续杯子侧翻。
- 初态已双侧接触夹持、离初始支撑约 12.23cm，物体 XY 距放置目标约 1.2mm。235 步初始化动作包含物理抓取准备，发生在模型采样之前，不进 PPO 数据，也不进这段视频。
- base 最终目标距离约 33.69cm、倾角 11.73°；RL 后约 24.15cm、倾角 82.53°。此例的旧目的地偏置在本轮 RL 前已经存在，不能归因于本次 RL 才出现的过拟合。

从此例能确认“保留旧场景目的地/动作模板”。它将黄白杯而非书搬过去，不能据此断言语言完全没有作用。严格证明语言依赖需要在相同可行动作初态上只改变指令做成对对照。相关行为与 [When Instructions Retrieve Trajectories](https://arxiv.org/abs/2609.39971) 对 π0.5 指令—动作绑定的分析相符；论文不是对本次具体原因的验证。

## 上一版实现的缺口

1. **pick 成功没有约束原地或高度下降。**实际条件为夹持且 lift>=5cm 连续40步；移动中也能计时，下降但仍高于5cm仍可成功。下降到阈值以下仅清零计时，无专门扣分或终止。
2. **原来报告的 16/24 不能理解为原地稳定抓取。**16 个旧规则成功案例中14个在终止时水平偏移超过10cm，13个超过15cm；实际是在持物搬运中达到高度保持条件。
3. **place 确实从真实已夹持状态开始。**模型不负责 reset 脚本抓取；视频第0帧已持物。后续再抬起/搬运是策略动作。放置不应因场景中恰有盘子就自动绑定该盘子；下一版按 RPent 已带至目标附近的条件设置局部区域。
4. **奖励对技能关键环节不完整。**pick 势函数为 `-eef_distance + clamp(lift,0,.1) + .1*grasped`；place/upright 为 `-target_xy_distance - .05*tilt/90 - max(lift,0)`；整体差分塑形乘 .1。没有独立的持续水平越界成本，也没有接触、合适时机释放、撤离或保持进展反馈。
5. **扶正的塑形容易惩罚必要前置动作。**90°变为0°的角度势能差乘权重仅 .005；抬高10cm在 place/upright 的高度项会降低约 .01 的势能。初期缺少成功奖励时，必要的抓起再旋转没有清晰的阶段引导。潜势差形式本身不等于合理的任务势函数。
6. **加权势函数可以偏好“近但倒下”。**place-01 最终的 XY/倾角/高度势函数总值：base约 -0.42888，RL后约 -0.33728。更近和更低可以抵消更差的倾角；这不是终点成功，但说明中间信号没有充分区分稳定放置与倒在附近。
7. **采样结束后重置限制了长任务数据。**32个chunk×8步=最多256步/12.8秒，然后下一批重新初始化，尽管环境上限400步/20秒。13,742/17,195次有效尝试被这样切断。bootstrap 本身可以用于 PPO 片段；问题是后续没有继续原环境，长任务后段及其成功信号缺失。
8. **物体和背景关联很强。**inventory 对每个物体类型仅保留第一个原场景，白杯、黄白杯等没有系统跨多个原场景训练；位置只做约±1.2cm、yaw约±20°扰动，不能充分打破场景捷径。

这些是代码和记录能够确认的事实。它们分别导致多大性能损失，现有单次试训不能做因果定量归因。

## 下一版任务与奖励建议

| 技能 | 成功定义建议 | 局部约束建议 |
|---|---|---|
| Pick | 真实夹持并抬离支撑>=5cm；进入保持阶段后，在高度容差和低速条件下连续2秒，立即成功结束 | 原物体XY为锚；推荐5cm免罚区、15cm硬边界；保持阶段下降超过1cm（容忍短暂物理抖动）判失败、负奖励 |
| Place | 从有效真实夹持且位于局部目标上方开始，只需调整、下降、接触、释放、撤离并稳定4秒 | 目标区域显式固定；桌面先用8cm容差，盘上按单独明确任务的规则；不因原场景目标自动迁往盘/盒 |
| Upright | 从需要恢复的侧翻状态开始；抓法不限，必要提升和旋转后就近放稳；倾角<=5°并稳定4秒 | 初始落稳XY为锚；推荐8–10cm局部区，20cm硬边界，允许必要的重新抓持空间 |

高度下降惩罚仅用于 pick 的“已经抬起、正在保持”阶段；不能用于 place 的下降，也不能直接套到 upright 的必要调整过程。高度用物体参考点测量，不用夹爪高度代替；厘米级容差需按物体/物理抖动校准，不能逐帧严格要求单调不下降。

水平惩罚主要约束物体相对锚点的位移，夹爪允许在局部空间内找接触和撤离。越出局部免罚区后按每秒累计负奖，超过硬边界失败；不要单纯惩罚所有水平动作。必须配合抓稳、受控下降、稳定接触、条件释放和保持的正向进展，否则可能鼓励不动。中间事件只记一次或按进展给分，避免反复夹放刷分；放置的接触/释放奖励需与位置、倾角、速度、支撑条件绑定，避免高空松手拿奖励。

## 次数与后续验证

17万对应抓取171,944个动作块，不是17万条完整任务；抓取有效尝试7,971次。扶正有115,751个chunk、3,971次有效尝试，但没有终点成功。数据量绝不能等同有效探索；目前首先是目标/奖励/截断/初始化和数据覆盖问题，不能凭这一轮认定只差更多次数，也不能排除修复后仍需更多训练。

建议顺序：

1. 固定白杯、黄白杯、摩卡壶，从真实物理轨迹建立少量成功/失败对照，检查原地抓稳、搬走、掉落、稳定放下、扔下、不动等行为是否按预期排序。先验证任务评分。
2. 采样片段结束后保留环境和保持计数，下一轮同步新策略后继续，任务成功/失败/真正超时才 reset。初始化脚本仍排除出 PPO。
3. 相同物体跨多个原场景、相同场景不同合法目标/指令，保持原物理参数。使用可行的成对指令，例如同一手持状态“保持不动”与“在此放下”，检查模型是否切换技能；place 提示采用明确局部语义。
4. 做相同基础模型、相同种子/初态池、相同动作预算的小型对照：修复采样+旧奖励；修复采样+新奖励。另保留不更新的 base 参考。把示范热身作为后续独立因素，避免一次改变所有因素后无法解释结果。
5. 扶正持续零成功时，先建立20–50条真正成功的多样物理示范或已验证的恢复子阶段，再做适量 BC 热身及 PPO；失败脚本不当成功示范。必要时再比较更通用 base 或语言融合处的 LoRA，而不是先假定解冻一定有效。

下一版视频需显示目标物体、完整指令、策略版本、策略开始标记、局部边界、水平偏移、抬升/保持参考高度和计时、阶段及奖励分项。此分析没有应用上述改动。
