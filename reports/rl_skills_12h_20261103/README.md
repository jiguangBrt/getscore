## 验证与限制

三卡实测约 251–255 BF16 TFLOPS、约 1.1TB/s 设备内存拷贝；这只是微基准。模型 batch8 采样约 16.4 块/秒，batch16 约 20.8 块/秒。端到端吞吐还受物理初始化、仿真和更新影响。

16 环境、三卡梯度、4 次更新及恢复后的第 5 次更新已验证；完整 batch512 更新约 10.2 秒。旧概率重算误差为 0，三份梯度合并与整批计算最大差 `1.19e-7`，checkpoint 张量精确恢复。3 小时保存/评测使用预检的人工推进时钟验证，正式任务使用真实时钟。

初次 BF16 预检曾因改变微批次大小产生 log-prob 偏差，已停止并修复。正式代码固定保留原 batch8 分组，异常时停止，不能以放宽检查绕过。恢复从完整更新边界重新生成环境，不宣称能够恢复到轨迹中途。

扶正的少量预检仍为零成功。32 次真实物理脚本示范尝试没有满足完整成功判据，未作为训练数据；因此本轮没有 BC 示范热身，扶正能否在预算内学会仍有不确定性。所有最终效果以本轮实测为准。
