01 · 数据怎样走过系统
本机 · 启动与提示词启动器 → RPent配置、预算、官方任务与工具接入。保存 configuration / run.log。
本机 · CLI 进程Codex SDK → CLIapp-server / stdio；提交 33,730 字符初始文本，经本地 MCP 访问工具。
云端 · 规划模型GPT-6 Astra / low接收文本与工具观测；返回公开说明、像素选点和工具参数。
本机或远程 · 执行RPent 工具分流move_to 等走脚本控制；pi0_pick 走远程 π0.5。
本机 · 仿真与归档环境更新 → 再观察写入 states、相机图像和视频；工具返回给 GPT，进入下一轮决策。
脚本分支：7 次 move_to + 闭合 + 释放
GPT 给坐标或夹爪命令 → RPent 本地控制器 → LIBERO 环境 → 新状态。该分支不调用 π0.5。
VLA 分支：2 次 pi0_pick → 16 次推理
图像 + 8D 机器人状态 + 本次子指令 → 本地 HTTP 8113 → 远程 WebSocket 8008 → π0.5 返回 [10,7] 动作，每次执行前 5 个 → 更新观测后再推理。
回传的是图像与状态，不是让 GPT 直接输出全部底层动作。服务器提供动作推理，本机承担仿真。SAM3 8114 已配置，但这轮没有 segment 调用。

      
02 · Codex CLI 如何被唤起
  1. 启动脚本准备本地环境
    清除继承的 Python/Conda 路径，进入本项目虚拟环境；选择 scripts.run_libero_codex。
  2. 启动器检查已有 ChatGPT 登录
    选用 SDK 配套 CLI，移除子进程的 API key 变量；启动适配层，再调用 RPent CLI。没有为本轮提供 API key。
  3. RPent 建立本地 MCP 工具服务
    本轮地址为 http://127.0.0.1:40257/mcp/。环境服务地址在 env_server.log 中；RPent 准备模板和任务参数。
  4. Python SDK 启动 Codex app-server
    SDK 0.163.0 使用子进程的标准输入/输出进行 JSON-RPC；调用 thread_start，再 thread.turn(prompt)。模型选择 gpt-6-astra，推理强度 low。
  5. 消费事件、执行工具、写日志
    Codex 发起 MCP 调用，RPent 执行；事件逐条写入 stream.jsonl，公开文字与摘要写入 codex_*.txt，结果最终汇总至 transcript。
本轮精确的 RPent 启动参数
SDK 启动机制与代码来源
CLI 命令形式按配套 SDK 源码解释；历史进程完整 argv 未单独录制。RPent 启动参数来自本轮 configuration.json。
