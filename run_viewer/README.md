# 本地实验回放

实验过程统一使用 `run_viewer` 复盘，直接读取 `outputs/` 中的原始记录。旧的手工 `review/` 目录已删除，历史材料可从 Git 历史查看；后续不再生成或维护该目录。

在 getscore 目录运行：

```bash
./scripts/run-viewer.sh
```

打开 http://127.0.0.1:8765，默认读取 `/home/jh/getscore/outputs/long120_1027`。其中是最新的 120 个真实实验文件夹（原有 107 项与更新的 13 项），不使用软链接。也可以输入该目录或某次实验目录；输入 `outputs` 会自动进入 `long120_1027`。“重新读取”用于刷新正在写入的记录。可用 `--port 8766 --default-path /本机/实验目录` 修改默认端口和目录。其他批次及旧结果已归档至 `outputs/_archive/`。

实验目录统一命名为 `仿真名-试验编号-语言模型名-动作模型名`，例如 `long-original-9-gpt6-gawm`。选择区按这个顺序提供四个横向下拉框，分别选择后自动查找并打开对应目录；不存在的组合会提示未找到实验。仿真名当前为 `long-original` 和 `long-swap`，语言模型标识为 `none`（纯策略）、`gpt6`、`kimi`，动作模型标识为 `gawm`、`pi05`。直接打开实验链接也可切换其他组合。归档实验存放在 `outputs/_archive/runs/`，不进入默认列表；可直接输入归档路径回放。

Long 实验沿用相同命名规则。2026-10-27 整理后的 `long120_1027` 包含 120 个真实目录；旧批次的兼容软链接已移除，对应路径记录在归档批次的 `case-locations.json`。迁移清单及派生元数据备份保存在 `_archive/records/consolidate-long120_1027-*`。原始日志、轨迹、观测和视频保持不变；配置及统计中的文件位置已更新。

看到启动地址后，终端会持续等待网页请求，这是正常运行。保持该终端开启，在浏览器中访问地址即可；`Ctrl+C` 停止服务。启动脚本自动使用项目的 `.venv`，不需要先运行 `source .venv/bin/activate`。

页面提供总耗时、动作时间、工具调用、token 四项汇总和一条按时间排列的事件列表。点选事件查看启动输入、模型公开文字、调用参数、返回结果及前后观测；支持主相机/腕部切换、图片放大、动作片段和文字搜索。滚动到整条时间轴下方可播放完整实验视频，独立支持播放、暂停、拖动进度和全屏；切换实验时自动换为对应视频，未保存视频时隐藏播放器。

解析只用 Python 标准库和浏览器原生 JavaScript，无模型、外部资源或上传；服务只监听本机，只读原始文件，不执行日志中的命令。

## 数据与计时

- 读取 RPent 的 `configuration.json`、`run.log`、`*.stream.jsonl`、`transcript_*.json`、`states.json`、相机图片与 `episode.mp4`。兼容本项目 GAWM、π0.5 和 fake 规划器保存的记录。
- 总耗时采用 RPent 的 `elapsed_s`，旁注给出包含启动的日志跨度。动作时间为仿真视频时长，旁注给出帧数及动作工具的实际执行耗时，两种时间不混算。
- 工具数包含原始事件中的本地命令与 MCP 调用。Turn 按 Codex 累计 token 更新划分，重复通知去重；token 总数为输入加输出，缓存及 reasoning 分别包含在其中。
- 展示保存的公开文字和实际返回的推理摘要，不补写未返回的内部推理。没有独立时间戳的 token 通知标为约值；fake 记录按原始消息顺序显示，缺失时间留空。
- 前后图片只关联实际保存的观测。只读工具可能显示同一画面；历史观测另行标明。动作片段依据该项目的动作帧计数规则定位，只有合计与 MP4 帧数一致时才启用。
- LIBERO 的事件图片（含腕部和放大图）按策略输入的方向显示，与完整视频保持一致；原始标定文件不改动。规划器收到的图片还包括标定方向的观测，标定像素坐标应以原文件为准。图片按原始比例完整显示，并标注分辨率；本项目 LIBERO 策略输入和视频为 256×256，高清观测为 1024×1024，正方形视野来自实验相机配置，回放页面不额外裁切或扩展视野。
- 缺失或不完整的记录会提示，不猜测时间或动作结果。该页面不是任意日志格式的通用解析器。
- 任务描述后显示成功、失败、运行中、运行中断或结果未确认。优先使用最后一份环境观测的成功标记，缺失时读取 transcript 的 `environment_success` 或配置中的 `task_success`；模型自行声称成功不算环境成功。失败的结束类型按运行记录归类为步数上限、模型结束但目标未达成、规划轮数上限或结束原因未记录；超时和异常显示为运行中断。LIBERO 本身没有抓取失败、掉落、错放等统一失败类型，`truncated` 在本项目的 RLinf 包装层表示达到动作步数上限。模型结束说明保留原文并标为自述，不能作为 LIBERO 的原因标签。

验证：`env -u PYTHONPATH PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest tests/test_run_viewer.py`（隔离本机 ROS 的 pytest 插件）。

选定的 13 项 2000 步实验复用原 120 项的整理函数，补齐 `00-planner.stream.jsonl`（Kimi）、`native-action-counts.json`、任务审计、命令轨迹与 `artifact-completeness.json`。可运行 `.venv/bin/python scripts/package_selected_long_2000.py` 重新整理，只读取已保存的记录，不调用模型或仿真。续跑记录的时间轴与 `episode.mp4` 只覆盖追加段；`episode-full.mp4` 保留原 1000 步加追加段的连续回放。恢复时自动续执行的旧动作块单独显示，不计作新的模型工具调用；加载 Kimi 历史会话时回放的旧文字不计入本次时间轴。原始规划器未返回 Token 用量时显示“未提供”，不将缺失值解释为实际消耗 0。
